# Community Solutions: design

Date: 2026-11-07. Status: draft for the owner's review.

**Owner** means the owner decided it. **My call** means I chose it and the owner can overrule it while reading.

## 1. Why

Saved queries, workbooks and tools are made one user at a time today. Sharing is a workbook file passed by hand
([workbooks design §9.3](2026-11-06-workbooks-design.md)), and getting new content into everyone's Kustodian means a
release. The owner wants a catalog: a `Solutions` folder in this repo, one subfolder per solution with a manifest and its
queries, workbooks and tools, listed in a **Community Solutions** section of the app, installable without downloading a new
version (**Owner**).

What comparable products do, and what this design takes from them:

- **Microsoft Sentinel Content hub:** a solution is a versioned package bundling content; the list shows Installed and
  Update available and can update in bulk; installed items are templates, so a user's edited copy is never overwritten by
  an update. Packages bump their version on every change.
- **Elastic prebuilt rules:** tracks per rule whether the user modified it; unmodified rules update on their own, modified
  ones get a filter and a diff to choose from.
- **Velociraptor Artifact Exchange:** labels community content as not officially supported and warns that some of it runs
  binaries; advises installing what you need rather than everything.
- **Grafana.com dashboards:** on import, the user maps the dashboard to their own data sources (here: tools to their own
  executables, §7.3).

## 2. Goals

- A catalog read from `Solutions/` in this repo's `main` branch, listed in the app, so content ships without a release
  (**Owner**).
- A solution can hold **saved queries**, **workbooks** and **tools** (**Owner**).
- Install, update and uninstall from the app. Updates never overwrite what the user changed (Sentinel/Elastic model).
- The solution lists the **permissions** it needs; the app shows what is missing and offers **Grant permissions** for what
  it can grant (**Owner**).
- A PR that adds or changes a tool gets an **extra review step** in CI, with GitHub Copilot doing a first security review
  (**Owner**).

## 3. Non-goals (v1)

- Catalogs other than this repo's `Solutions/`: no custom or private catalog URLs (**Owner**: official only in v1). Also no
  import of a solution from a local folder or zip (**My call**: it would be a source without the CI review; the existing
  workbook file import stays).
- Dependencies between solutions, ratings, download counts, comments.
- Field-by-field three-way merge on update (Elastic). v1 offers keep mine / take theirs / keep both per item.
- Snippets and settings as solution content.
- Publishing from the app (an "Export as solution" that opens a PR). Authors add folders by PR as with any change.

## 4. Anti-goals

- **Installing or updating a solution adds or changes a command the user did not see and tick.** Every tool, new or with a
  changed command or arguments, is shown in full and is unticked by default (§7.3). This keeps the workbooks anti-goal
  ("opening a shared file runs, or brings in, a command") true for anything not explicitly accepted.
- An update overwriting a query, workbook or tool the user edited.
- A solution being able to grant itself write permissions. The Grant button only ever asks for read-only Graph permissions
  (§8).
- Anything running on install. Installed workbooks and queries run only when the user opens and runs them.
- Content fetched from anywhere but this repo, or used without matching the hash the index lists.

## 5. Repo layout

```
Solutions/
  index.json                      generated by CI on main, never edited by hand
  entra-risky-users/
    solution.json                 the manifest
    README.md                     shown on the solution's page
    queries/<item>.json           SavedQuery shape, minus id/createdAt/modifiedAt
    workbooks/<item>.json         the workbook file shape (workbooks design §9.2)
    tools.json                    optional; the tools.json shape, see §7.3
```

The folder name is the solution id: lowercase letters, digits and `-`, 3–64 characters. `<item>` file names are the item
ids within the solution, same rule. Tools sit in one file per solution so CI can watch one path (§9).

### 5.1 Manifest (`solution.json`)

```json
{
  "version": 1,
  "id": "entra-risky-users",
  "name": "Entra risky users",
  "solutionVersion": "1.2.0",
  "description": "Weekly review of risky users and their sign-ins.",
  "author": "frodehus",
  "support": "kustodian",
  "categories": ["identity"],
  "sources": ["graph", "hunting"],
  "minAppVersion": "0.9.0",
  "requires": {
    "graph": ["IdentityRiskyUser.Read.All", "AuditLog.Read.All"],
    "roles": ["Security Reader"],
    "licenses": ["AAD_PREMIUM_P2"],
    "azure": "Reader on the subscriptions you query"
  },
  "content": {
    "queries": ["risky-users", "risky-signins"],
    "workbooks": ["weekly-review"],
    "tools": ["Confirm compromised"]
  }
}
```

- `support`: `kustodian` (maintained by the owner) or `community`. Shown as a badge; community solutions carry Velociraptor's
  caveat ("not maintained by Kustodian; review before running").
- `solutionVersion`: semver, bumped on every change (CI enforces, §9).
- `minAppVersion`: older apps list the solution with "Needs Kustodian 0.9.0" in place of Install.
- `requires.graph`: Graph permission names, checked against the token. `roles`, `licenses` and `azure` are shown as text;
  `licenses` uses the SKU part numbers `ITenantLicenses` already reads, so it can show granted / missing.
- `content` lists every item; CI fails a folder with files the manifest doesn't list, or the other way round.

### 5.2 `index.json`

Generated by a CI job on every push to `main` that touches `Solutions/`: each manifest in full, plus every file's path and
SHA-256. One file means the app needs one request to list the catalog, which stays clear of GitHub's anonymous API limit
(60 requests per hour).

## 6. Fetching

- The app reads `https://raw.githubusercontent.com/FrodeHus/kustodian/main/Solutions/index.json` when the Community
  Solutions section opens, and at most once per hour otherwise (**My call**). Item files are fetched on install or update
  and must match the SHA-256 in the index, or the install stops with "The download didn't match the catalog. Try again
  later."
- The last index is cached in the data folder so the section opens offline, saying when it was fetched.
- Size limits are the existing ones (saved query text 1 MB, workbook 2 MB, 100 widgets) plus 64 KB for `tools.json` and
  256 KB for `README.md` (**My call**).
- The README renders with the workbook Markdown widget's renderer and the same link rules.

## 7. Install, update, uninstall

### 7.1 Provenance

Every installed item records where it came from: `{ solutionId, solutionVersion, itemId, upstreamHash, contentHash }`.
`upstreamHash` is the catalog file's SHA-256 at install or last update; `contentHash` is the SHA-256 of the item's
**content fields** as installed. Saved queries get an optional `origin` field on `SavedQuery`; workbooks, which the host
keeps as opaque JSON, get an `origin` property. Installed tools are recorded in a new `solutions.json` in the data folder
(the user's `tools.json` keeps its current shape). An item is **modified** when its current content hash differs from the
recorded one.

Content fields (**My call**: moving, renaming or saving an item unchanged must not mark it modified):

- **Query:** `source`, `text`, `parameters`, `options`. Not id, name, folder or timestamps.
- **Workbook:** everything except `id`, `name`, `folder`, timestamps and `origin`, with `saved.id` links mapped back to
  solution item ids and the linked-query copies (workbooks design §9.2) left out.
- **Tool:** `args` and `mode`, with identity by tool name. The executable path the user picked is not content. A tool
  renamed or removed in `tools.json` is no longer tracked.

Content hashes are computed over canonical JSON (sorted keys, no whitespace) after the service's defaults are filled, so
an app upgrade that adds a default field doesn't mark items modified.

`solutions.json` also lists installed solutions and their versions, so the catalog can show Installed and Update available.

### 7.2 Install

The review reuses the workbook import review (workbooks design §9.3, screen 7), extended:

- what is in the solution, its sources, its support tier and README;
- the **requirements** panel (§8);
- the **tools** panel (§7.3);
- Install. Queries and workbooks go in a library folder named after the solution, with new ids; the workbooks' links to
  the solution's queries are rewritten to the new ids, as import already does. Folder names follow the existing rule
  (1–80 characters, no `/`).

Install all, or untick items to skip them (Velociraptor's advice). Skipped items are not tracked and are offered again on
the next update.

### 7.3 Tools

A solution's tool is the user's `tools.json` shape with one change: `command` is a **program name** (`az`, `pwsh`), not a
path, because full paths differ per OS and per machine (**My call**). In the review each tool shows:

- name, mode and the full argument list, as the existing Run tool dialog shows a command line;
- an **executable** field, filled with the first existing match from common install locations for that OS
  (`/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`, `C:\Program Files\...` and the like) and editable with the file dialog;
- a checkbox, **off** by default. Only ticked tools with an executable are written to `tools.json`, through
  `ExternalToolService.SaveAsync`, so its validation applies.

A solution tool with the name of a tool the user already has is shown side by side with theirs: keep mine (the default) or
replace. Workbook buttons match tools by name, so keeping theirs keeps the buttons working.

### 7.4 Update

Update available shows when the index's `solutionVersion` is newer than the installed one. If that version needs a newer
app, the card says "Update needs Kustodian x.y" and the installed version keeps working; the index holds only each
solution's latest version (**My call**). Items whose catalog file is unchanged (same `upstreamHash`) aren't listed at all,
modified or not. The update review lists each remaining item as one of:

- **unchanged by you**: updated without asking (the Sentinel/Elastic default), with a checkbox to hold it back;
- **modified by you**: keep mine (default), take theirs, or keep both (theirs installed alongside with "(updated)" in the
  name and a new id); a diff of the query text is shown, and for workbooks a summary (widgets added, removed, changed).
  With keep mine, the item stays tracked and is offered again on the next update. With keep both, the origin moves to the
  new copy, the solution's workbooks link to it, and the user's copy becomes their own, untracked (**My call**);
- **new**: as on install;
- **removed upstream**: kept, and its origin cleared, so it becomes the user's own (**My call**);
- **tools**: any tool whose command name, args or mode changed is shown as on install and is unticked. An unchanged tool
  isn't shown. This holds even when the user never edited the tool (§4).

"Update all" in the catalog applies only the unchanged-by-you items and never tools; anything else waits for the review.

### 7.5 Uninstall

Removes the items not modified by the user and asks about the modified ones (remove, or keep as your own). Tools are
listed with a checkbox each, ticked only for unmodified ones, because workbooks other than the solution's may use them.

## 8. Requirements and Grant permissions

The requirements panel shows each `requires` entry as met, missing or unknown:

- **Graph permissions**: from the current token's scopes. Missing read-only ones get one **Grant permissions** button that
  asks for all of them in one consent request, through the same flow as today's **Grant permission…**
  ([EntraPermissions.md](../../EntraPermissions.md#grant-permission)): Microsoft's consent screen decides, and the sign-in
  is refreshed afterwards. Same limits: no button with the Azure CLI client, and none for write permissions, which show as
  "Needs *X*. Ask an administrator." (**Owner** asked for the button; the limits are **my call**, keeping today's rules.)
  A user who can't consent gets the existing "An administrator has to grant…" message with the list of what to ask for.
- **Roles** and **Azure access**: text only ("Needs the Security Reader role"); consent can't grant them.
- **Licences**: met or missing from `ITenantLicenses`.

Missing requirements never block an install; the panel also shows as a badge on the catalog card.

## 9. Repo and CI

- **Validation job** on PRs touching `Solutions/`: manifest schema; ids and folder names; every file listed and every
  listed file present; queries and workbooks load through the same rules the app's services apply; KQL parses with the
  parser the app uses; `solutionVersion` raised when anything in the folder changed; no tenant or subscription GUIDs, no
  e-mail addresses, no results in workbook files; `minAppVersion` at most the `Directory.Build.props` version with its
  minor raised by one, so content for a merged but unreleased feature can land (**My call**). A workbook's tool button may
  name a tool that isn't in the solution's own `tools.json`; the install review treats it like an unmatched button on
  import (workbooks design §9.3).
- **Owner review for all of `Solutions/`** (**Owner**): a new `CODEOWNERS` file makes the owner's review required for any
  change under `Solutions/`, which also covers who may mark a solution `support: "kustodian"`. The owner may narrow this
  later (for example to tools and the `kustodian` tier only) if the community grows; nothing else in the design depends on
  it.
- **Tool review**, when a PR adds or changes any `Solutions/*/tools.json` (**Owner**), on top of the owner review:
  - a job labels the PR `tools-change` and comments every new or changed tool's full command line;
  - a branch ruleset requests a **Copilot code review** automatically, with a path-specific instruction file
    (`.github/instructions/solution-tools.instructions.md`) telling it what to flag: shell interpreters as the command
    (`bash`, `sh`, `pwsh`, `cmd`), download or install commands, write or delete API calls, row values placed into URLs or
    scripts, `batch` tools sending rows to a network target. Copilot comments; it cannot approve or block, so the
    owner's review is the gate.
- **Index job** on push to `main`: regenerates `Solutions/index.json` and commits it. The app ignores any index entry whose
  files don't hash as listed.

## 10. The app

- **Community Solutions** is a section reached from the side panel next to Saved and Recent (**My call**: the builder may
  make it a tab instead if the side panel is too narrow for cards).
- The list: search; filters for category, source, support tier, installed, update available; each card shows name,
  description, author, support badge, item counts, requirement badges, and Install / Update / Installed.
- The solution page: README, items, requirements, and the review flows of §7.
- Installed queries and workbooks show a small "from *Solution*" marker in the library, and "modified" when their hash
  differs.
